1. Detection & Inference Hot Path (highest ROI)

Current: PredictionLogic owns ONNX session, letterbox, NMS, mask regions. FP16 sibling + TensorRT path already present. SessionOptions lifetime fixed. Loop error tolerance = 10 consecutive failures.
AreaImprovementWhy
Async / double-buffer inference Overlap capture of frame N+1 with inference on frame N. Two pinned float buffers + ring of 2 DenseTensors. Removes ~1 frame of pure sequential latency on CUDA/TRT.
Dynamic batch / multi-ROI Optional second pass on sticky-target crop only (smaller tensor) when FOV is large. Higher effective resolution on the active target without full 640² cost every frame.
Class / team filtering at tensor level Early prune by class ID before NMS when game-specific models expose team/enemy classes. Less post-process work; fewer false positives into tracker.
Adaptive image size Runtime switch 320/416/512/640 based on measured FPS budget and target distance. Maintain 144+ Hz on weaker GPUs without config reload.
ORT arena + thread pool isolation Dedicated OrtEnv / session for AI loop; never share with UI/OCR/Jev HTTP. Prevents UI freezes during engine rebuild or first Run().
Model warm-start cache Persist TensorRT engines + DirectML graph cache keyed by GPU + model hash. Kill the 30 s–2 min first-load tax after driver updates.
Output tensor layout auto-detect Already partial; harden for YOLOv5/v8/v9/v10/RT-DETR mixed layouts and dynamic axes. Custom models stop breaking silently.

2. Aim Pipeline (AimController / filters / selection)

Current: Proportional controller with high-strength near-linear mode, accumulator, max-step floor 400. OneEuro + PID adaptive + NSA Kalman exist. Sticky selector with challenger hysteresis.
  • Unified smoother chain — Configurable pipeline: Raw → OneEuro → Kalman lead → PID → AimController step. Expose order + enable flags in AimProfile. Today pieces exist but composition is rigid inside AimingAction.
  • Ballistic / acceleration lead — Extend Kalman state to [x,y,vx,vy,ax,ay] or use constant-acceleration model when track history ≥ 6 frames. Better on strafing + vertical jumps.
  • Humanization layer — Micro-jitter + Bezier / minimum-jerk paths (MovementPaths already partially present) scaled by strength and distance. Optional “human curve” intensity on profile.
  • Bone / hitbox offset — Per-class aim-point bias (head/chest/pelvis) driven by box height ratio + configurable head % slider. EditHeadArea UI exists — wire it fully into TargetTrack aim point.
  • Disengage / re-acquire rules — AimDisengageRule is present; expand to velocity-based break (target exceeds max track speed), occlusion frames, and “lost behind cover” OCR/region conditions.
  • Sub-pixel residual carry across backends — AimController already accumulates. Guarantee the same fractional carry survives MouseManager → GHub / Razer / ddxoft / SendInput / Gamepad stick so micro-corrections never quantize differently per method.
  • FOV-aware strength curve — Strength = f(distance_to_edge_of_FOV). Soften near edges so the bot doesn’t fight the user’s turn when target is leaving FOV.

3. Smart Neural Anti-Recoil + RecoilPredictor

Current: Patch capture, phase-correlation residual, EMA baseline, RNN/analytic prior, micro-steps. Pure vision path (good).
  • Weapon / class classifier feed — Use detection class or a tiny secondary head to select PriorY/PriorX tables and PredictWeight. Different weapons need different vertical gain and burst curves.
  • Burst-phase state machine — Explicit phases: pre-fire, initial kick, sustained, spray, cooldown. Reset residual history and baseline only on true LMB edges + shot-count delta, not on every frame.
  • Adaptive PredictWeight — Lower weight when phase-correlation confidence is high and residual is consistent; raise when correlation fails (smoke, flash, low light).
  • Dual-path compensation — Optional hybrid: recorded RecoilPatternPlaybackAction + SmartNeural residual. Pattern handles deterministic first 8–12 shots; neural cleans the stochastic tail.
  • GPU phase correlation — Move OpenCvSharp phaseCorrelate off CPU when CUDA is available (or use a small ONNX correlation net). Current path can be the loop’s second-largest cost after detection.
  • Per-profile neural weights — Serialize residual history stats + learned gain offsets into AntiRecoilProfile so the model “remembers” a user’s sensitivity and weapon set.

4. Capture Stack

Current: DXGI primary, GDI fallback, ProcessCapture, CaptureSource abstraction.
  • Desktop Duplication + multi-monitor affinity — Pin duplication to the adapter that owns the game window; auto-rebind on display change / HDR toggle / exclusive fullscreen switch.
  • Shared surface / zero-copy path — When possible, keep the captured frame in GPU memory and feed ORT CUDA/TensorRT directly (avoid CPU round-trip + BGRA→RGB conversion).
  • Frame timestamp + latency budget — Stamp every capture; drop frames older than N ms instead of processing stale data. AIManager already has FpsCapHelper — couple it to age, not only rate.
  • HDR / wide-color handling — Explicit tone-map or sRGB conversion path so detection doesn’t collapse under HDR games.
  • Process capture reliability — Better window-handle refresh, DPI awareness, and “game lost focus but still rendering” detection so the loop doesn’t thrash between DXGI and GDI.

5. Input / Mouse / Gamepad

Current: Unified InputSender, MouseManager backends (GHub, Razer, ddxoft, SendInput), gamepad right-stick aim, HidHide.
  • Backend health probe — Continuous light heartbeat; automatic failover (GHub → Razer → SendInput) with UI notice when a driver silently dies.
  • Relative vs absolute calibration — SensitivityCalibrator exists — expand to full pixels-per-count measurement per backend and store in profile so the same strength feels identical across methods.
  • Stick aim curve editor — Response curves for gamepad aim (deadzone, expo, saturation) instead of linear mapping of pixel error → stick deflection.
  • Input event bus telemetry — Latency histogram from “detection ready” → “Move() returned” exposed in DebugOverlay. Identifies which backend is the bottleneck.
  • Safer HidHide integration — Explicit device whitelist UI + restore-on-exit guarantee so users don’t lose physical mouse after crash.

6. Tracking, Sticky Aim, Prediction

Current: TargetTracker + TargetTrack + StickyAimSelector + KalmanPrediction + PredictionFilter.
  • ID stability under occlusion — Short-term predicted ghost track (Kalman coast) so sticky ID survives 3–8 frames of missing detection.
  • Multi-target priority model — Score = distance + confidence + class priority + “threat” (facing camera / closer to crosshair velocity). Configurable weights in AimProfile.
  • Team / friendly fire filter — When model supports it, hard-exclude ally classes; optional color/outline heuristic for games without class IDs.
  • Prediction lead UI — Live visualization of predicted point vs current box on DebugOverlay / FOV overlay so users can tune lead time by eye.

7. AutoPlay / Learning / Jev / OCR

Current: AutoPlayLearningModel, AutoPlay actions, JevDecisionClient (HTTP), OcrService + condition evaluator, Ollama client.
  • Closed-loop AutoPlay — Record (state, action, outcome) tuples into ReplayBuffer-style storage; offline policy update or simple bandit for trigger timing / ability use.
  • Jev latency budget — Hard timeout + local fallback policy so a slow decision server never stalls the aim loop. Parallel non-blocking decision path only.
  • OCR region stability — Temporal voting + small tracking on OCR boxes so flicker doesn’t fire actions. Cache last good text for N frames.
  • Condition graph editor — Visual node editor for OcrTriggerCondition trees (already structured as nodes) instead of pure list UI.
  • Ollama / local LLM tool use — Structured tool calls for “should I reload / swap / hold angle” with strict schema so responses stay machine-parseable.

8. Profiles, Config, Persistence

Current: Rich AimProfile / AntiRecoilProfile / AutoPlayProfile, AppConfig, many settings classes.
  • Profile hot-swap without full AI restart — Swap strength, FOV, filters, recoil tables while loop runs; only reload model session when model path / provider changes.
  • Per-process auto-load — ActiveProcessSettings already exists — strengthen to automatic profile bind + capture source bind when process appears.
  • Config migration + schema version — Explicit version field + migrators so future fields don’t silently reset user data.
  • Import/export with dependency check — Profiles that reference missing models or backends warn instead of loading half-broken state.
  • Cloud / local sync optional — Encrypted profile pack (no account required) for multi-PC users.

10. Reliability, Diagnostics, Tooling

Current: AppDebugLog, CudaDiagnostics, PerformanceBenchmark, TensorRtInstaller, consecutive error counter, replay export.
  • Structured crash / hang reports — On MaxConsecutiveLoopErrors or unhandled exception: dump last N replay frames + config snapshot + ORT/provider state + backend name.
  • Self-test suite on startup — Optional: capture probe, model load, one dummy Move(), backend ping. Surface results in launcher before main window.
  • Benchmark mode — Fixed synthetic detections → measure end-to-end aim latency distribution (p50/p95/p99). Already have PerformanceBenchmark — wire to a one-click UI action that writes a report.
  • Log levels + ring buffer — Keep last 5–10 k lines in memory; export on demand. Avoid unbounded file growth.
  • Build / packaging — Separate CUDA vs DirectML vs CPU publish profiles; keep native DLLs out of the wrong package. Single-file already used — document which natives must stay external.

11. Architecture / Code Hygiene

  • Clear ownership of the AI loop thread — AIManager owns the thread; actions must be re-entrant-safe or explicitly documented as “AI-thread only”. Avoid hidden UI thread affinity inside actions.
  • Interface tightening — IPredictionLogic / ICapture / IAction are good. Push more of the filter and controller surface behind small interfaces so AimingAction stops growing into a god object (440 lines already).
  • Reduce static singletons — ReplayBuffer, some managers — prefer explicit composition from AIManager / App for testability (Core.Tests already exists; expand coverage to tracker + controller math).
  • Nullability & warnings — Project already uses NRT and NoWarn cleanup. Finish remaining string? / disposable patterns in capture and ONNX paths so Release builds stay clean.
  • CHANGELOG.md is empty — Populate from the actual SmartNeural / crash-fix / hot-path work so users and future diffs have a timeline.
