1. Project Overview

PowerAim V4 is an open-source, AI-powered game aim-assistance and automation tool for Windows. This archive targets .NET 10 (net10.0-windows / net10.0), ships as a WPF application, and uses ONNX Runtime to run real-time object-detection models against a screen-capture feed. Detections drive mouse and virtual-controller input for aiming, recoil control, triggering, and full AutoPlay bot behaviour.

Upstream origin is Florian Gilde’s fgilde/AI-Ming (community models also merged from Babyhamsta/Aimmy). This tree is labeled PowerAim_V4_SmartNeural_Updated: Smart Neural anti-recoil, RAR-merge / crash fixes, MUST hot-path work, and build-warning cleanup. The published binary is stamped with assembly name PixelCraft and a rotating brand-name pool at build time.

Intended design posture
The codebase is explicitly structured as a gameplay-assistance / automation tool with dedicated anonymization, process/window identity spoofing, PE VERSIONINFO patching, and humanized input timing. Those subsystems exist to reduce visibility to process monitors and anti-cheat fingerprinting.

4. AI / Inference Pipeline

Core Inference Loop

Orchestrated by AIManager (singleton). Owns an ICapture backend, an IPredictionLogic (ONNX) session, and a list of IAction instances. A dedicated background thread runs the loop with consecutive-error tolerance (MaxConsecutiveLoopErrors = 10) so transient DXGI device-lost events do not tear down the session. CreateAsync builds the potentially slow inference session off the UI thread (TensorRT first-build can take 30 s–2 min).

PredictionLogic (ONNX)

  • YOLOv8-oriented; auto-detects input resolution, class count, and channels-first vs channels-last output layouts (including dynamic axes).
  • Reusable resize buffer to avoid per-frame allocation when FOV ≠ model size.
  • Class filtering via configurable target class IDs / modes; detection mask regions applied post-decode.
  • FP16 sibling model path for CUDA/DirectML; TensorRT builds FP16 from FP32 when preferred.
  • SessionOptions lifetime is owned carefully — options must outlive the session (documented crash fix in this tree).
  • KD-tree (Supercluster.KDTree) used for nearest-neighbor candidate lookup in the broader aim path.

Execution Provider Chain

TensorRT → CUDA → DirectML → CPU

Gated by presence of TensorRT libs and a valid NVIDIA device index (DXGI adapter ordering). Failures fall back with diagnostics. Default SessionOptions are DirectML-safe (MemoryPattern off, Sequential execution).

5. Aiming Subsystem

Centered on AimingAction plus AI/Aiming/: AimController, TargetTracker, TargetTrack, TargetSelector, NsaKalmanFilter, OneEuroFilter, PidAimSmoother.

Smart path (default)

  1. Target selection — nearest / sticky selection in model space; challenger hysteresis in TargetSelector.
  2. Tracking (opt-in) — StrongSORT-style: NSA Kalman on (cx, cy, aspect, height) + velocity, Hungarian assignment on IoU/distance cost, Mahalanobis gate (χ² 99% for 4 DoF ≈ 13.28). Replaces older greedy SORT.
  3. Aim point — head / body / fractional box point; head area editable via UI.
  4. Smoothing — EMA, One-Euro (adaptive cutoff), or adaptive dual-axis PID (gains scale with box size, confidence, speed).
  5. AimController — frame-rate-independent proportional move, high-strength near-linear mode, sub-pixel accumulator, max-step floor raised to 400 for large flicks.

Profiles

AimSettings holds multiple AimProfile objects (per-profile aim key, FOV, smoothing, disengage rules, OCR conditions). Effective profile is resolved from which aim key is held — supports head vs body on separate binds in the same session.

Legacy prediction

PredictionMethod enum retains Kalman, Shall0e, and WiseTheFox EMA predictors for the legacy path. Velocity-aware Kalman state lives in the prediction manager for lead-time support.

6. Anti-Recoil Subsystem

Four modes, gated by ToggleState.AntiRecoil and active AntiRecoilProfile.Mode:

Legacy
Fixed X/Y compensation from HoldTime / FireRate / XRecoil / YRecoil. Deterministic, game-agnostic.
Pattern Playback
Replays recorded (dx, dy) samples while trigger held; loops; per-weapon JSON patterns.
Image-Based
Phase-correlation on screen patches; EMA baseline isolates intentional aim from recoil impulse.
Smart Neural
RecoilPredictor anticipates kick from burst index + residual history; combined with phase-correlation residual, EMA baseline, vertical/horizontal gains, micro-steps, pure vision (no game memory).

All compensation routes through InputSender.Move, so gamepad right-stick aim receives anti-recoil as well.

7. AutoPlay / Bot Engine

AutoPlayGameAction (~1.3k LOC) is a multi-layer bot:

LayerCadenceRole
Hot path (heuristic)Every frame (<1 ms)Combat aim/shoot, movement, sprint, crouch, reload — non-blocking.
Strategic (Ollama)~3–5 s backgroundVision/LLM guidance when configured; failures surface on decision snapshot.

Decision transparency uses AutoPlayDecisionSnapshot and an activity ring buffer (AutoPlayLogEntry) for the debug / decision panel. Learning path captures behaviour into AutoPlayLearningModel via AutoPlayLearningAction.

8. Screen Capture

ICapture implementations selected by CaptureSource:

  • DxgiScreenCapture — primary Desktop Duplication path (Vortice.DXGI / D3D11).
  • GdiScreenCapture — fallback BitBlt path.
  • ProcessCapture — window/process-targeted capture.
  • ScreenCapture — facade / default wiring used by AIManager constructors.

AIManager chooses backend from target type; DXGI device-lost is treated as recoverable within the consecutive-error budget. Sensitivity calibration can measure pixel drift via phase correlation after known mouse impulses.

9. OCR Subsystem

OcrService runs Tesseract (Tesseract.NET) on user-defined regions with OpenCV binarization preprocessing and optional auto-download of eng.traineddata. Results are exposed as an observable latest-per-region dictionary.

OcrConditionEvaluator evaluates condition trees (AND/OR/NOT style nodes) to gate aim, triggers, and AutoPlay. UI: region painting overlay + dialogs; condition builder for profiles.

10. Input & Controller Subsystem

All synthetic output goes through InputSender:

  • Mouse: backends selected by MouseMovementMethod — MouseEvent, SendInput, LG HUB, Razer Synapse, ddxoft, or Gamepad (virtual right-stick). Legacy separate “use controller for aim” toggle was folded into this enum.
  • Gamepad senders: ViGEm, vJoy, DualShock4, Titan Two, internal, XInput emulation, reporting wrapper.
  • Keyboard: SendInput / InputSimulator key sequences.
  • HumanTiming: non-uniform timing / Bezier-style jitter on sequences to reduce regularity.

Bindings & mapping

InputBindingManager + StoredInputBinding unify mouse/keyboard/gamepad binds. Controller mapping profiles, HID enumeration, HidHide helpers, and device-hide UI support virtual substitution without conflicting physical devices. AutoTriggerAction adds cooldowns, charge vs DownAndUp modes, OCR gates, and detection-presence requirements.

Findings

Critical — Design intent vs multiplayer ToS
The product is built for automated aim, recoil, trigger, and bot behaviour in games, with explicit anti-detection. Use in online multiplayer typically violates publisher Terms of Service and can trigger permanent bans or account action.
Low automated test coverage
Only JevResponseParser and PythonVersion are covered. No unit tests for ONNX decode, tracker/Hungarian math, AimController, SmartNeural residual path, config migration, or InputSender backends. Regressions depend on manual playtesting.
Global mutable state
AppConfig.Current and AIManager.Instance are process-wide singletons. The AI loop and UI both touch config without a universal snapshot/lock strategy. Some maps use ConcurrentDictionary; many fields do not.
OpenCV Mat lifetime in SmartNeural
SmartNeuralAntiRecoilAction retains a queue of gray Mat frames. Eviction/disposal on pause, profile switch, or reset must stay correct or native memory can grow across long sessions.
Empty CHANGELOG + third-party “Updated” label
CHANGELOG.md is empty. SmartNeural / crash-fix / hot-path work is not recorded in-tree. Downstream consumers should diff against upstream fgilde/AI-Ming when auditing supply-chain changes.
Strong provider fallback & session ownership
TensorRT→CUDA→DirectML→CPU chain, explicit SessionOptions lifetime notes, and CreateAsync off-UI loading are solid production-oriented choices for heterogeneous GPUs.
Tracking & control quality
StrongSORT-style tracker with NSA Kalman + Hungarian + Mahalanobis, plus OneEuro/PID/AimController stack, is unusually thorough for this class of tool and is well commented.
Config migration pattern
Schema versioning and legacy field migration reduce breakage for long-lived user profiles — important given profile depth.
17. Summary & Recommendations

Technical summary

This SmartNeural Updated tree is a large, coherent C# / .NET 10 WPF application (~54k LOC of C#) with a real multi-provider ONNX pipeline, StrongSORT-derived tracking, adaptive smoothers, four anti-recoil strategies (including vision + neural feed-forward), a substantial AutoPlay stack (heuristic + Ollama + Jev), multi-backend mouse and virtual gamepad output, OCR gating, and a full custom UI system. Documentation quality on the hot AI paths is high; automated tests and CHANGELOG hygiene are not.

Recommendations (engineering)

PriorityAreaRecommendation
High Tests Unit-test ONNX layout parse, NMS/class filter, TargetTracker assignment, AimController accumulator, config migration, and Jev client timeouts.
High Thread safety Publish a read-only config snapshot (or versioned view) to the AI loop each tick instead of live mutable AppConfig fields.
Medium Hot path latency Double-buffer capture/inference; drop aged frames; optional GPU phase-correlation for SmartNeural.
Medium Disposal Audit Mat queues and InferenceSession/options pairs on every stop/reset path.
Medium CHANGELOG / provenance Document SmartNeural, crash fixes, and hot-path changes; keep a clear diff policy vs upstream.
Low DI / testability Reduce reliance on static Instance/Current for managers that need multi-instance or pure unit tests.
Low Aim UX Expose AimController step caps and high-strength thresholds as profile sliders; live predicted-point overlay.

Operational note

From a pure software-engineering standpoint the archive is advanced and intentionally structured. From a product policy standpoint it is purpose-built for automation that multiplayer publishers prohibit. Treat deployment and distribution decisions accordingly; this report does not endorse online multiplayer use.
